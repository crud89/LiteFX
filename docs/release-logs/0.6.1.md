# LiteFX 0.6.1 - Alpha 06

- Update toolchain to LLVM 21. (See [PR #197](https://github.com/crud89/LiteFX/pull/197))
- Improve shader build scripts. (See [PR #202](https://github.com/crud89/LiteFX/pull/202)
	- Allow to specify entry point names and Vulkan environment when compiling with DXC.
	- Add new `TARGET_ADD_SHADER_PROGRAM` helper.
	- Improve `pcksl` helper; optionally support `#embed`, if available.
- Add missing primitive topologies for adjacency and patch lists. (See [PR #201](https://github.com/crud89/LiteFX/pull/201) and [PR #209](https://github.com/crud89/LiteFX/pull/209))
- Allow overlapping push constants ranges between shader stages. (See [PR #205](https://github.com/crud89/LiteFX/pull/205))
- Add `tryAllocate` method to virtual allocators. (See [PR #207](https://github.com/crud89/LiteFX/pull/207))
- Add method to query adapters using a user preference. (See [PR #210](https://github.com/crud89/LiteFX/pull/210))
- Homogenize synchronization across backends. (See [PR #223](https://github.com/crud89/LiteFX/pull/223))
	- Vulkan queues now also guarantee command buffer execution order.
	- Barriers should no longer require backend-specific image layout transitions in edge-cases.
	- The engine expects images to be in `Common` layout and leaves them as such.
	- Freshly allocated image should be treated as `Undefined` now.
- Implement command allocator sharing. (See [PR #225](https://github.com/crud89/LiteFX/pull/225))
	- Command allocators/pools are now shared over command buffer allocations.
	- Command buffers are now scoped one-time objects.
	- Render passes can now be recorded onto user-supplied command buffers.

**🌋 Vulkan:**

- Update Vulkan SDK to 1.4. (See [PR #196](https://github.com/crud89/LiteFX/pull/196))
- Allow to supply custom instance and device extensions. (See [PR #198](https://github.com/crud89/LiteFX/pull/198), [PR #203](https://github.com/crud89/LiteFX/pull/203) and [PR #204](https://github.com/crud89/LiteFX/pull/204))
- Fix render pipeline constructor argument order. (See [PR #206](https://github.com/crud89/LiteFX/pull/206))
- Expect `VK_KHR_unified_image_layouts` by default to simplify image layout management. (See [PR #220](https://github.com/crud89/LiteFX/pull/220))
- Implement support for descriptor heaps through `VK_EXT_descriptor_heap`. (See [PR #222](https://github.com/crud89/LiteFX/pull/222))
	- Replace descriptor buffers (`VK_EXT_descriptor_buffer`) and remove proxy heap types (`VK_EXT_mutable_descriptor_type`).
	- Add new `IDescriptorRange` type to represent direct allocations from global descriptor heaps.
	- Remove obsolete `descriptorHeap` and `runtimeArray` shader reflection hints.
	- The `DynamicDescriptors` device feature now validates SM 6.6 support and enables `VK_KHR_shader_untyped_pointers` extension.

**❎ DirectX 12:**

- Validate root signature cost and reject counted buffers. (See [PR #222](https://github.com/crud89/LiteFX/pull/222))

**🐞 Bug Fixes:**

- Fixed two issues with the assets and shader build scripts: (See [PR #202](https://github.com/crud89/LiteFX/pull/202))
  - An issue where the asset build script could not copy multiple files to the same directory.
  - An issue where the shader build script did not properly pick up the `OUTPUT_NAME` target property.
- Fix several synchronization issues. (See [PR #220](https://github.com/crud89/LiteFX/pull/220))

**⚒️ Build:**

- Restructured build scripts into re-usable workflows and actions. (See [PR #216](https://github.com/crud89/LiteFX/pull/216))
- Remove all submodules from the repository (including vcpkg).
- Fix an issue that caused tests to timeout in CI builds. (See [PR #221](https://github.com/crud89/LiteFX/pull/221))

**📖 Documentation:**

- Improve website and documentation. (See [PR #217](https://github.com/crud89/LiteFX/pull/217), [PR #218](https://github.com/crud89/LiteFX/pull/218) and [PR #219](https://github.com/crud89/LiteFX/pull/219))
	- Switch documentation backend to MrDocs.
	- Support versioning for documentation. This will start with the next release; previous releases are not ported.
	- Switch website backend to MkDocs (to be replaced with Zensical in the future).
	- Overhaul website design.
	- Rewrite the tutorials and add walkthroughs for the samples.
